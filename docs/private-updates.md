# Серверные гайды DiscordikXP

Исходники и архивы аддона находятся в публичном репозитории
`Ishimitsu14/DiscodicXP-WoW-Forever`. Публичная сборка содержит бесплатные стартовые
маршруты Орды 1–22, но не содержит купленных гайдов или ключа расшифровки.
Купленные гайды хранятся только в сервисе
админки и на игровых компьютерах, которые скачали их по ключу устройства.
API и админка находятся в `DiscodicXP-WoW-Forever-AdminPanel`.

## Пользовательский сценарий

1. В закрытой веб-админке выбрать исходный `.txt` гайда.
2. Дождаться публикации новой ревизии пакета.
3. В Windows-лаунчере нажать «Обновить гайды». Он получает последнюю ревизию
   через `/api/v1/guides/latest`, проверяет пакет и атомарно заменяет
   `UserGuides/ForeverHorde.lua`. Повреждённые данные не меняют установленный файл.
4. Выполнить `/reload` в игре или запустить WoW. Скачивание выполняет лаунчер;
   Lua-аддон не делает сетевых запросов.

Код аддона распространяется отдельным архивом со стартовыми маршрутами
и пустым файлом серверных гайдов. Первую установку выполняют при закрытом WoW,
затем загружают купленные гайды кнопкой
лаунчера. При следующих обновлениях кода уже установленный файл сохраняется,
если старая и новая версии поддерживают `guideUpdates: 1`.
Релизы кода не изменяют базу пакетов, загруженных через админку.

## Хранение и авторизация

Админка требует авторизацию, выдача гайдов — действующий ключ устройства.
Учётные данные не включаются в Lua, архив аддона или репозиторий.
Файлы лицензии и авторства исходного движка сохраняются.

## Прогресс при изменении маршрута

При смене digest серверного пакета аддон очищает метаданные и кэш неподходящих
разделов. Текущий шаг и прогресс остаются в SavedVariables. Старые ручные
импорты сохраняются в `legacyGuides`, но больше не загружаются поверх файла
сервера. Сопоставление позиции при перестановке шагов требует проверки в игре:
сохранение файла прогресса само по себе его не гарантирует.

## Проверки

Сборка не принимает `--guide`; её проверка отклоняет купленные маршруты и ключи импорта
в архиве. Регрессии проверяют сохранение серверного файла при обновлении
аддона, целостность пакета и переход со старого кэша без сброса текущего шага.
Проверку принятия заданий, стрелки и `/reload` выполняют в игровом клиенте.
