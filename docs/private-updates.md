# Приватные обновления DiscodicXP

Статус: согласованная схема, реализация в работе.

Первый этап — обновление полного архива аддона через собственный сервер.
Исходники сервиса и Windows-лаунчера добавлены в `server/` и `launcher/`;
развёртывание и проверка на реальном сервере выполняются отдельно.
Игровые компьютеры подключаются к сервису по собственному ключу и не получают
доступ к GitHub. Подробности: [launcher.md](launcher.md).
Сценарий веб-админки и применения обновления гайда внутри игры ниже остаётся
следующим этапом.

Репозиторий: `Ishimitsu14/DiscodicXP-WoW-Forever`, приватный.
Админка доступна через браузер с любого устройства. Прогресс персонажа
остаётся локальным на каждом компьютере и не передаётся в GitHub.

## Пользовательский сценарий

1. В закрытой веб-админке выбрать исходный `.txt` гайда.
2. Проверить список разделов и опубликовать новую версию.
3. Помощник Windows получает сборку через собственный сервис и готовит обновление
   в папке аддона. Повреждённый пакет не заменяет установленный.
4. Кнопка в аддоне «Применить обновление» перезагружает интерфейс и
   применяет уже скачанную версию. Скачивание выполняет внешний помощник.

Изменения кода аддона распространяются отдельным архивом. Для первого
подключения помощника и новых файлов может понадобиться перезапуск клиента;
обычные обновления текста гайда используют заранее созданный файл.

## Хранение и авторизация

Исходники и готовые пакеты находятся в приватном GitHub. Админка размещается
в закрытом Sites. Доступ к приватному GitHub получает только сервер;
учётные данные не включаются в Lua, архив аддона или репозиторий.
Файлы лицензии и авторства исходного движка сохраняются.

## Прогресс при изменении маршрута

Старый stepId зависит от строки исходного файла. В новой версии требуется
сопоставление текущего шага по командам, идентификаторам заданий и действий.
Сдвиг из-за вставки предыдущих шагов не должен переносить персонажа на другую
цель. Неоднозначное сопоставление показывается пользователю, а не считается
успешным сохранением позиции. Выполненные в игре задания проверяет клиент.

## Проверки

Публикация только в приватный репозиторий. Загрузка и применение пакета,
проверка целостности, откат при ошибке, повторное применение без дубликатов,
вставка и удаление шагов перед текущим, сохранение ручных отметок, отдельный
прогресс на двух устройствах. Экраны админки проверяются через Playwright.
