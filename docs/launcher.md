# Windows-лаунчер DiscordicXP

Лаунчер устанавливает обновления аддона и синхронизирует прогресс
персонажей между компьютерами через свой HTTPS-сервер. С версии 0.4.0 отдельная
кнопка обновляет гайды из админки при открытом WoW.

Клиентский код находится в `launcher/` (WPF, .NET 9), дополнения аддона — в
`addon/`. Сервер обновлений, админка, SQLite и API прогресса перенесены в отдельный
репозиторий [DiscordicXP-WoW-Forever-AdminPanel](https://github.com/Ishimitsu14/DiscordicXP-WoW-Forever-AdminPanel).
Инструкции развёртывания, создания администратора и ключей находятся в README
серверного репозитория. В этом репозитории серверного кода больше нет.

## Подключение

1. Администратор создаёт аккаунт с BattleTag и отдельный ключ для каждого компьютера.
2. В лаунчере адрес `https://153.76.170.60` уже заполнен. Укажите ключ
   компьютера и папку `Interface\AddOns` нужного клиента Forever.
3. Нажмите «Проверить» или «Обновить аддон». Установка выполняется при закрытом WoW.

Ключ шифруется Windows DPAPI и хранится в `%LOCALAPPDATA%\DiscodicXP\Launcher`.
Токен GitHub на игровые компьютеры не передаётся. Старые ключи сервера обновлений
продолжают работать для скачивания сборок, но для прогресса нужен новый ключ
из админки, связанный с аккаунтом.

## Гайды из админки

Нужен аддон 0.5.0+ с `guideUpdates: 1` в build.json. После первого обновления
перезапустите WoW. Далее загрузите исходный `.txt` в разделе «Гайды» админки,
в лаунчере нажмите «Обновить гайды», а в игре выполните `/reload`.
Обновление гайдов не требует закрытия игры; установка кода аддона и перенос
прогресса по-прежнему выполняются при закрытом WoW.

Лаунчер получает метаданные `/api/v1/guides/latest`, затем неизменяемый JSON
`/api/v1/guides/packages/:sha256` по ключу компьютера. Проверяются версия формата,
число разделов, размер до 16 МиБ и SHA-256. Lua создаётся локально из строк;
исполняемые директивы гайда не принимаются. Заменяется только заранее объявленный
`UserGuides/ForeverHorde.lua`, резервная копия сохраняется рядом с ним.
При повторной загрузке того же содержимого файл не меняется. Последующие полные
обновления аддона сохраняют текущий комплект гайдов. Файлы WTF не перезаписываются.

## Синхронизация между компьютерами

Нужен аддон 0.4.0+ и лаунчер 0.2.0+. На каждом компьютере сначала войдите нужным
персонажем с включённым аддоном, затем нормально выйдите и закройте WoW.
Это создаст файл прогресса с GUID персонажа.

1. На первом компьютере выберите персонажа и нажмите
   «Синхронизировать». Прогресс отправится на сервер.
2. На втором компьютере подключите ключ того же аккаунта, найдите того же
   персонажа и нажмите «Синхронизировать». Подтвердите загрузку облачной версии.
3. Если лаунчер остаётся открытым и включено автосохранение, после закрытия WoW
   он отправит прогресс выбранного персонажа сам. Иначе нажмите «Синхронизировать».
4. На первом компьютере синхронизация загрузит новую версию, если его локальный
   прогресс не менялся со времени последней синхронизации.

Лаунчер 0.2.2+ ищет персонажей при открытии и выборе папки AddOns. После первого
выхода новым персонажем нажмите «Найти», чтобы перечитать список.
Поддерживаются папки `<realm>\<character>` и `<realm-id>\<character>-<home-realm>`;
имя, сервер и GUID берутся из сохранения аддона.

Автосохранение отслеживает закрытие процесса WoW раз в 5 секунд, пока лаунчер
открыт. Оно действует только на выбранного персонажа. Загрузка серверной версии
всегда требует явного подтверждения; автосохранение останавливается при конфликте.
Если лаунчер закрыт или сеть недоступна, отправьте прогресс вручную перед сменой компьютера.

Если прогресс изменился на обоих компьютерах, автоматическая синхронизация
останавливается. «Загрузить с сервера» явно выбирает серверную версию, сохраняя
локальную рядом с исходным файлом в `DiscodicXP.lua.dxp-backup-<id>`.
Для возврата локальной версии закройте игру, сохраните текущее содержимое отдельно
и восстановите нужную резервную копию как `DiscodicXP.lua`.

Первое подключение компьютера с уже существующим серверным прогрессом предлагает
загрузить его с резервной копией местного. Потеря локального `sync-state.json`
приводит к тому же поведению; она не разрешает перезапись облачной версии.
Смена серверного адреса или аккаунта создаёт отдельную историю синхронизации.

Перед заменой файл проверяется повторно, сохраняется резервная копия и
выполняется атомарная замена. Если WoW запущен или файл изменился за время
запроса, загрузка отменяется. Лаунчер читает Lua как литеральные данные и не
исполняет полученный с сервера код.

Переносится весь файл **конкретного персонажа**:
`WTF\Account\<account>\<realm>\<character>\SavedVariables\DiscodicXP.lua`.
Он содержит DXPCData, DXPCTrackingData, DXPCComms и DXPCSettings, включая текущий
маршрут, шаги, отметки, завершённые точки и историю маршрутов.
Общие SavedVariables аккаунта, импортированные тексты гайдов и другие аддоны
не переносятся. На компьютерах нужен одинаковый набор маршрутов. GUID защищает
от восстановления на другого персонажа с похожим именем.

BattleTag в админке задаётся владельцем сервера. Аддон сообщает наблюдаемый
BattleTag, если клиент предоставляет BNGetInfo; отсутствие API не мешает работе.
Пароль Battle.net не запрашивается. BattleTag не используется как ключ авторизации.

## Обновление лаунчера

Начиная с 0.3.0 лаунчер проверяет собственную версию при запуске. Проверку можно
повторить кнопкой «Проверить обновление» в верхнем блоке. Когда доступна новая
версия, нажмите «Обновить и перезапустить». Сборка скачается внутри приложения;
текущий exe будет заменён по тому же пути, включая переименованные копии из Downloads.
Для перехода с 0.2.2 и старше потребуется один раз скачать новую сборку вручную.

Обновления самого лаунчера загружаются с закреплённого `https://153.76.170.60`,
без ключа компьютера и независимо от поля сервера аккаунта. JSON содержит версию,
размер, SHA-256 и неизменяемый путь к exe; HTTPS-перенаправления не принимаются.
Перед запуском проверяются хеш, размер и встроенная версия приложения.

Отдельный процесс из `%LOCALAPPDATA%\DiscodicXP\Launcher\updates` дожидается
закрытия старого лаунчера, сохраняет предыдущий exe и заменяет его атомарно.
Новая версия подтверждает запуск; при ошибке перезапуска восстанавливается
предыдущий файл. После успешного запуска временные файлы удаляются.
Настройки и зашифрованный ключ находятся вне exe, файлы аддона и прогресса при
самообновлении не меняются. Для обновления лаунчера закрывать WoW не требуется.
Для замены exe нужны права записи в папку, из которой он запущен.

## Приватные обновления

Сервер получает последнюю обычную GitHub Release и один пакет
`DiscordicXP-<версия>-personal.zip`, проверяет размер и SHA-256 и кэширует его.
Старое имя `DiscodicXP-<версия>-personal.zip` также поддерживается.
Лаунчер проверяет целостность архива, безопасные пути и версию сборки до установки.
Лаунчер не принимает HTTPS-перенаправления. Замена папки аддона сохраняет предыдущую
в `.DiscodicXP-backup-<id>`; при ошибке установки она восстанавливается.

## Публикация через CI/CD

Push в `main` серверного репозитория обновляет API и админку через GitHub Actions.
Релиз `launcher-v<версия>` в клиентском репозитории собирает и доставляет лаунчер
на сервер отдельным workflow. Настройка секретов и порядок выпуска: [cicd.md](cicd.md).

## Локальная сборка и проверки

На компьютере разработчика требуется .NET SDK 9. Сборка использует текущий
исправленный .NET 9 Runtime из официальных release metadata; можно явно
указать `-RuntimeFrameworkVersion`. На игровом компьютере установка .NET
не нужна, пакет содержит runtime. Переход на .NET 10 LTS нужен до завершения
поддержки .NET 9 (10 ноября 2026, [официальные metadata](https://builds.dotnet.microsoft.com/dotnet/release-metadata/9.0/releases.json)).

```powershell
.\launcher\publish.ps1
dotnet run --project tests/launcher/LauncherChecks.csproj
# Только проверки обновления лаунчера (можно при запущенном WoW):
dotnet run --project tests/launcher/LauncherChecks.csproj -- --self-update-checks
# Проверка реальной замены и отката на временных копиях двух exe:
dotnet run --project tests/launcher/LauncherChecks.csproj -- --self-update-checks <new-exe> <previous-exe>
npm.cmd test
```

`publish.ps1` формирует автономный `dist/launcher-win-x64/DiscordicXP.Launcher.exe`.
Векторный исходник иконки находится в `launcher/Assets/LauncherIcon.xaml`.
Перед публикацией `create-icon.ps1` создаёт ICO с размерами от 16 до 256 пикселей.
Проверки лаунчера проверяют архивы, DPAPI, безопасные пути, чтение SavedVariables,
резервные копии, две папки клиента, перенос отметок и tracking, сохранение базовой
ревизии после перезапуска и конфликты между компьютерами.
Серверные интеграционные тесты запускаются отдельно в серверном репозитории.
Они не заменяют проверку входа и выхода в реальном клиенте Forever.
